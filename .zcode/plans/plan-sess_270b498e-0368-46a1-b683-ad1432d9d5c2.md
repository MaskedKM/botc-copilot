# 实施计划：#115 Butler 投票限制校验

官方规则已核实（Butler Wiki）：管家每夜选一名除己外玩家做主人；**次日管家只能在主人也投赞成（举手）的提名上投赞成**——主人不投赞成则管家此票无效，逐提名约束。数据链路完整：主人经夜间面板（#110，Butler 已在夜序）录入为 InfoDeclaration(`{"playerId":X}`)；投票在 `NominationEntrySheet`。设计遵循「警告不阻止」（App 无法确认管家真实身份/主人改口，由用户裁决）。一个 PR，3 commit，关闭 #115。

## Commit 1 — 纯函数（`nomination_rules.dart`，可单测）
- `butlerVoteRestricted({required Vote? butlerVote, required Vote? masterVote}) → bool`：管家 forVote && 主人非 forVote → true（管家此票无效）。
- `butlerMasterOf(List<InfoDeclaration> declarations, int butlerPlayerId) → int?`：取该管家最新 butler 声明 payload 的 playerId（最新 = 当夜所选，治理当日投票；无记录 null）。解析失败/null 返回 null。
- 二者纯函数，覆盖死主人死票赞成（算"投票"）、管家非赞成（不限）、主人未录（null，不校验）等边界。

## Commit 2 — UI（`nomination_entry_sheet.dart`）
- import `dependency_chain_provider.dart`（gameDeclarationsProvider）。
- build 中：watch `gameDeclarationsProvider`；用 `latestClaimWithSelf` 算各玩家最新声明 → 找出声明管家；`butlerMasterOf` 取主人；组装 `butlerInfo: Map<int, ({int masterSeat, bool restricted})}>`（仅含已录主人的管家）。
- **行内提示**（`_QuickVoteGrid._chip` / `_VoteRow`，传 `butlerInfo`）：管家 chip/行追加「·主人X号」；`restricted==true` 时显 ⚠（图标/警示色）。
- **提交前确认**（`_submit`，警告不阻止，与 Virgin/详细漏录同模式）：从最终 `_votes` + butlerMaster 重算命中者；非空则弹「管家 X号 赞成但主人 Y号 未赞成，官方此票无效。仍要提交？」，返回不阻断。
